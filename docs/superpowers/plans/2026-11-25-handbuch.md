# Handbuch und Hilfe im Programm – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein deutsches Handbuch (Markdown, PDF) mit Hilfe-Seitenleiste im Programm, automatischen Bildschirmfotos und Vorgaben in neuen Dateien.

**Architecture:**
- Die Markdown-Kapitel in `docs/handbuch/` sind die einzige Quelle für alle drei Ausgaben:
  - Vite bindet sie ins Programm ein (Seitenleiste).
  - Ein Node-Skript setzt sie zu HTML zusammen, das Chrome headless als PDF druckt.
  - GitHub zeigt sie direkt an.
- Bildschirmfotos entstehen in einem eigenen WebdriverIO-Lauf unter Linux, mit einer Beispieldatei aus einem Rust-Beispielprogramm.

**Tech Stack:**
- Rust (`verwaltung_core`, `verwaltung_app`) und Svelte 5 mit TypeScript.
- Darstellung mit `marked` und `DOMPurify`, Tests mit Vitest.
- Node 22 mit `node:test`.
- WebdriverIO 9 und tauri-driver, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-25-handbuch-design.md`

## Global Constraints

- Alle Texte für Nutzer sind deutsch in Schweizer Schreibweise: „ss“, nie „ß“.
- Das Handbuch spricht in der Sie-Form.
- Knopf- und Menünamen im Handbuch stehen **fett und genau wie im Programm**.
- Mitgliederkategorien genau so: „Mitglied mit Geschäft“, „Mitglied ohne Geschäft“, „Mitglied ohne SBC“, „Kein Mitglied“.
- Label-Gruppe „Aufnahme“ (für Betriebe und Personen) mit dem Label „provisorisch“.
- Keine echten Personendaten im Repo. Beispieldaten sind erkennbar fiktiv. `docs/documentation/` bleibt ignoriert und wird nie gelesen oder committet.
- Die Hilfe braucht kein Internet. Ausnahme ist nur „Handbuch als PDF“, das `https://github.com/Zer0SkiLL/b-cker-verwaltung/releases/download/v<Version>/Handbuch.pdf` öffnet.
- Externe Links in gerendertem Markdown sind nie klickbar.
- TDD. Abdeckung in `ui/src/lib` ab 80 %. Die CI-Befehle müssen grün sein:
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo test --workspace`
  - `pnpm --dir ui exec vitest run`
  - `pnpm --dir ui check`
  - `node --test 'scripts/*.test.mjs'`
- Commits haben die Form `<type>: <Beschreibung>`, mit deutscher Beschreibung aus Nutzersicht bei `feat`/`fix`, und enden mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Gearbeitet wird auf dem Branch `feat/handbuch`. Pushen auf diesen Branch ist erlaubt, damit der Bildschirmfoto-Workflow laufen kann. Merge nach main nur nach Rückfrage.

## Review Focus

1. **Hooks bleiben getrennt:** Wird zuerst ein Hilfe-Kapitel und danach der CHANGELOG gerendert, bleiben im CHANGELOG alle Links entfernt. Umgekehrt bleiben Kapitel-Links erhalten.
2. **Suche robust:** Leere Anfragen, Sonderzeichen wie `(`, `*` oder `[` und Umlaut-Varianten führen weder zu Absturz noch zu Regex-Fehlern.
3. **Hilfe überall:** Die Seitenleiste funktioniert auch auf der Startseite (ohne Sidebar-Layout) und in einer nur lesend geöffneten Datei.
4. **Tastatur:** F1 öffnet die Hilfe auch, wenn der Fokus in einem Eingabefeld liegt. Esc schliesst nur die Hilfe und lässt offene Eingaben und Dialoge unangetastet.
5. **Vorgaben nur in neuen Dateien:** Sie entstehen nur beim Anlegen, nie beim Öffnen einer bestehenden Datei. Ein späterer Excel-Import mit gleichen Kategorienamen erzeugt keine Duplikate.
