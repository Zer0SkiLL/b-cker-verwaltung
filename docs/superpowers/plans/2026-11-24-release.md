# Installer, Updates und Release Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatische Installer-Builds mit deutschen Release Notes, Update-Funktion und „Über das
Programm" im Programm, CI für jeden Push, E2E-Tests der Kernabläufe.

**Architecture:**
- **Versionen und Release Notes:** kleine Node-Skripte ohne Abhängigkeiten (`scripts/*.mjs`, Tests
  mit `node --test`) und `git-cliff`.
- **Workflows:** GitHub Actions `ci.yml` und `release.yml` (mit `tauri-action`).
- **Updater:** `tauri-plugin-updater`/`-process` in `crates/app`. Die Logik in der Oberfläche liegt
  in `ui/src/lib/updates.ts`.
- **E2E:** WebdriverIO + `tauri-driver` in `e2e/`.

**Tech Stack:**
- Node 22 (Root-`package.json` mit `@tauri-apps/cli@^2` und `git-cliff@^2`)
- tauri-plugin-updater 2, tauri-plugin-process 2, @tauri-apps/plugin-updater 2, @tauri-apps/plugin-process 2
- marked, dompurify
- webdriverio 9, tauri-driver

**Spec:** `docs/superpowers/specs/2026-11-24-release-design.md` (freigegeben)

## Global Constraints
- Kosten 0. Keine Dienste ausser GitHub Actions/Releases. Keine Telemetrie.
- Oberfläche und Release Notes auf Deutsch. **Commit-Beschreibungen ab jetzt auf Deutsch und aus
  Nutzersicht** (`feat: …`/`fix: …`); technische Commits als `chore`/`ci`/`test`/`docs`/`build`.
- Der private Updater-Schlüssel liegt **nie im Repo**. Er liegt in
  `~/.tauri/mitgliederverwaltung.key` (+ Passwort). Secrets setzen nur nach Zustimmung des Auftraggebers.
- Tag-Push und Veröffentlichen eines Releases nur nach Zustimmung.
- Der Branch `feat/release` wird zum Testen der Workflows auf GitHub gepusht (im Plan freigegeben).
- Ein Update schliesst vorher die Datei sauber (`close_file`). Ein nicht erreichbarer zweiter
  Sicherungsort ist nur ein Hinweis.
- TDD, Dateien < 400 Zeilen, Funktionen < 50 Zeilen, unveränderliche Daten im TS.

## Review Focus
1. Updater offline oder GitHub nicht erreichbar → still beim Start, verständliche Meldung nur bei
   manueller Suche.
2. Download/Installation scheitert nach dem Schliessen der Datei → Meldung mit „Erneut versuchen"
   und „Datei wieder öffnen". Kein Zustand ohne Ausweg.
3. `release.mjs` mit gleicher/kleinerer Version, unsauberem Arbeitsbaum oder nicht auf `main`
   → Abbruch vor jeder Änderung.
4. Release Notes ohne nutzerrelevante Commits (nur chore/ci) → ein Satz statt leerer Abschnitt.
5. Markdown aus CHANGELOG enthält HTML/Script → wird bereinigt angezeigt.

### Task 1: Versions-Werkzeuge, Release Notes, CHANGELOG
**Files:** Create `package.json` (Root), `scripts/version.mjs`, `scripts/notes.mjs`,
`scripts/release.mjs`, `scripts/*.test.mjs`, `cliff.toml`, `CHANGELOG.md`; Modify `.gitignore` (`/node_modules`)

**Produces:**
- `version.mjs`
  - `parseSemver(s) -> {major, minor, patch}` wirft bei ungültiger Eingabe.
  - `isGreater(a, b) -> boolean`.
  - `setCargoVersion(text, v) -> text`: nur die `version` in `[package]`.
  - `setJsonVersion(text, v) -> text`: erhält die Formatierung.
- `notes.mjs`: `extractSection(changelog, version) -> string | null` (Abschnitt `## [x.y.z]` bis zum
  nächsten `## `). CLI `node scripts/notes.mjs 0.1.0` druckt den Abschnitt, Exit 1 wenn nicht gefunden.
- `release.mjs <version>`:
  1. Prüft der Reihe nach: auf `main`, Arbeitsbaum sauber, Version grösser als `crates/app/Cargo.toml`.
  2. Führt die Tests aus.
  3. Setzt die Version in Cargo.toml, tauri.conf.json und ui/package.json.
  4. Erzeugt `git-cliff --tag v<version> -o CHANGELOG.md` (prepend), dann `cargo update -p verwaltung_app`.
  5. Commit `chore: Version <v>`, Tag `v<v>`, `git push --follow-tags`.
  - `--dry-run` zeigt nur den Plan.
- `cliff.toml`:
  - Gruppen „Neu" (feat), „Verbessert" (perf, refactor), „Behoben" (fix). Andere Typen ausgelassen.
  - Kopf `## [x.y.z] – TT.MM.JJJJ`.
  - Leerer Abschnitt → „Interne Verbesserungen ohne sichtbare Änderungen.".
- `CHANGELOG.md` mit handgeschriebenem Abschnitt `## [0.1.0]` „Erste Version" und Funktionsüberblick.

- [ ] Tests (`node --test scripts`):
  - semver parse/compare (0.10.0 > 0.9.0, gleich ist nicht grösser, „1.2" wirft)
  - setCargoVersion ändert keine Abhängigkeits-Versionen
  - setJsonVersion
  - extractSection (mittlerer und letzter Abschnitt, fehlend → null)
  - `cliff_groups_commits_in_german`: temporäres git-Repo mit feat/fix/chore-Commits →
    `npx git-cliff --tag v9.9.9 --unreleased` mit unserem `cliff.toml` enthält „### Neu" und
    „### Behoben", nicht „chore"
  - `cliff_only_chore_gives_sentence` (Review Focus 4)
  - `release_refuses_not_greater_version`, `release_refuses_dirty_tree` (release-Logik als Funktion
    `preflight({branch, clean, current, next}) -> string[]` mit deutschen Fehlern)
- [ ] RED → umsetzen → GREEN. Commit `chore: Werkzeuge für Versionen und Release Notes`.

### Task 5: Update-Funktion und „Über das Programm" in der Oberfläche
**Files:** Create `ui/src/lib/{updates.ts,markdown.ts}` + Tests, `ui/src/pages/settings/About.svelte`;
Modify `ui/src/components/NoticeBar.svelte`, `ui/src/pages/Settings.svelte`, `ui/src/lib/router.ts`
(Tab `about`), `ui/src/pages/Start.svelte`, `ui/src/App.svelte`, `ui/vite.config.ts` (`server.fs.allow`)

**Produces:**
- `updates.ts`:
  - Store `updateState`: `{kind:'idle'} | {kind:'checking'} | {kind:'none'} | {kind:'available', version, notes} | {kind:'installing', percent} | {kind:'failed', message, fileClosed: boolean}`.
  - `checkForUpdates({silent}): Promise<void>` (silent: Fehler → idle, sonst failed mit „Update-Prüfung nicht möglich (keine Verbindung?)").
  - `installUpdate(): Promise<void>`:
    1. `closeFile()`; ein Hinweis bei nicht erreichbarem zweitem Ort wird übernommen.
    2. `downloadAndInstall` mit Fortschritt.
    3. `relaunch()`.
    4. Fehler → `failed` mit `fileClosed: true`.
  - `reopenLastFile()`.
  - Abhängigkeiten (Plugins, api) als Parameter für Tests.
- `markdown.ts`: `renderMarkdown(md) -> string` (marked + DOMPurify).
- `About.svelte`: Version (`getVersion`), „Was ist neu?" (`CHANGELOG.md?raw`), „Nach Updates suchen", Repo-Link.
- `NoticeBar`: Update-Hinweis „Version X ist verfügbar" mit „Was ist neu?" (aufklappbar) und
  „Jetzt installieren", Fortschritt, Fehler mit „Erneut versuchen"/„Datei wieder öffnen".
  Prüfung beim Start in `App.svelte` (silent).
- `Start.svelte`: Ist bereits eine Datei offen (`sessionInfo()` gelingt), geht es direkt zu Adressen
  (nötig für E2E, robust bei Neuladen).
- [ ] Tests:
  - `updates.test.ts`: silent offline → idle; manuell offline → failed; Update da → available mit Notes;
    install Reihenfolge `closeFile → downloadAndInstall → relaunch`; Download-Fehler → failed mit fileClosed
  - `markdown.test.ts`: Überschrift, `<script>` entfernt, `onerror` entfernt
  - `NoticeBar.update.test.ts`: Knopf „Jetzt installieren" ruft `installUpdate`
  - `Start.test.ts`: offene Sitzung → Route addresses
- [ ] RED → GREEN, `pnpm --dir ui check`. Commit `feat: Updates direkt im Programm und Seite „Über das Programm"`.
